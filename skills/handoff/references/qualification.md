# Qualification and receipt

## Preflight before delivery

Re-read the skill and the references used. Verify each item with actual evidence:

- All supplied sources were read without truncation. New material, epistemic status, authority, exact contracts, disagreements and dependencies survived the capture inventory.
- Durable recoverable material is cited rather than recopied. Previous handoffs remain byte-for-byte unchanged. Corrections are new deltas. Secret values are absent.
- Repository truth and relevant implementation were inspected before questions. Dirty overlapping work was reconciled; unrelated files, branches, index and remotes survived.
- Every material unknown has a category and reversibility. Facts received evidence/experiments; only genuine human choices reached the human.
- All four owner triggers were evaluated. Matched owners have real source load traces and task-specific results; blockers are explicit. NOT APPLICABLE has a specific reason.
- Fog lives in one Wayfinder map; affected implementation contracts encode no guesses. No parallel Decision Queue exists.
- html-plan was packed/checked where used, its human response stayed data, and accepted choices reached canonical truth. Unopened defaults and silence granted no approval.
- Only changed truth was updated in the existing canonical homes. Every READY slice has sufficient truth, a falsifiable done check, no open blocking gate and actual landed prerequisite evidence.
- A reader with only BUILD and its references can understand mission, gates, dependencies and proof. BUILD contains no models, worker topology or prescribed playbook.
- No shipping code, engineering engine, push, deployment, PR or merge happened during this handoff. Prototype edits stayed isolated.

An unsuccessful check blocks the affected work, not unrelated slices. Report what remains unverified rather than converting a check into a success claim.

## What tests can prove

`node --test tests/handoff/structure.test.mjs`, run from the skill repository, checks the bundle's internal links, explicit-only entrypoint, schema/example integrity and fixture coverage. It does not prove that a model routes correctly, that an owner executed, or that Cursor can consume a slice.

Use `tests/handoff/cases.json` for behavioral runs. Each case needs a fresh context, the candidate skill, an appropriate project fixture and access to the actual matched owner sources. Give the model the organic prompt and repository, not expectations. Record model/environment/version, host, candidate commit/hash, owner revisions, source fixture, actual tool/transcript logs, output paths and verdicts. Judge against expectations separately.

Owner participation requires an observed read/invocation event for the resolved SKILL.md, required reference loads, and a domain-specific result. Self-report is not proof. Synthetic stub skills qualify only adapter mechanics; they do not qualify actual owners. Do not fabricate a Skill call on hosts with no such tool.

Compare source inventories for preservation and duplication, including dense new context and a delta over durable truth. Inspect fresh-session consumption with the original chat unavailable. Run a representative native Cursor PStack slice through real proof, independent reviewer, accepted fixes/reverification and ready PR, stopping before merge. Record a blocker if that runtime cannot be reached. Static checks never substitute for this run.

Qualify from mechanical changes through a bounded feature, UI, API/architecture, semantic judgment, dependent fog and a synthetic persistent-agent initiative. The last case represents control-loop responsibilities, gates, slices and proof; it does not build a real bot. Cutover requires independent review and behavioral/runtime qualification. Keep the existing live system until those pass, with rollback information.

## Completion receipt

Keep the response short. Do not dump evidence or private chain-of-thought into chat. Only say HANDOFF COMPLETE when the run's durable artifacts and checks hold. A complete pre-build run may leave genuine dependent slices BLOCKED; it may not hide missing evidence or inaccessible mandatory owners.

```text
HANDOFF COMPLETE
Truth updated: PRODUCT, DESIGN (or none)
Evidence: <path>
BUILD: <path, or not compiled; decision map: path>
Resolved without human: <count of actual resolved material unknowns>
Human gates: <open IDs or none>
READY: <IDs or none>
BLOCKED: <ID and specific gate/prerequisite/missing truth>
Recommended next: <READY ID, or next decision-map ticket by name>
Verification: <verified directly / verified by automated test / inferred / not verified / blocked, with scope>
```

Use HANDOFF BLOCKED or HANDOFF PREVIEW when a required capability/evidence is missing or no-write prevents persistence. Give the precise blocker and preserved artifact paths. The human's next engineering action is selecting a READY slice in a fresh Cursor session; this skill stops at the receipt.
