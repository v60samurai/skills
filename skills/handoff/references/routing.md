# Routing

Classify every material unknown before selecting a capability. Record its category, reversibility, affected outcome and smallest resolving action. A missing fact is not automatically human-owned.

| Category | Resolve with | Escalate when |
|---|---|---|
| FACT / TECHNICAL FORK | Inspect; research current primary sources; domain-model unclear language; reproduce, prototype or benchmark; compare real alternatives; challenge consequential decisions; choose supported reversible option | Evidence or access is unavailable, or the choice changes product/authority |
| HUMAN INTENT / PREFERENCE | Inspect first, propose a hypothesis and recommended answer, make consequences concrete, ask the actual owner | Missing truth lives with the human |
| IRREVERSIBLE / EXTERNAL AUTHORITY | Gather evidence and prepare a concrete proposal; record a Human Gate | Approval, credentials, spend, stakeholder authority, privacy/security acceptance or an irreversible action is required |

Use the smallest sufficient escalation, not every row as a ritual. Factual experiments should include their conditions, observations and limits. Consequential technical decisions can use Addy's doubt-driven review; obey its independent-review and external-CLI authorization boundaries. Do not claim a review happened without its evidence.

## Mandatory domain owners

Evaluate all four on meaningful work and record MATCHED or NOT APPLICABLE with a task-specific reason. A matched owner must participate through its actual source. An inaccessible or unsupported matched owner is BLOCKED with the source/tool limitation, not NOT APPLICABLE. Do not replace it with generic model reasoning. Only dependent work blocks.

| Owner | Mandatory trigger | Negative control | Result |
|---|---|---|---|
| brainstorm-stack | Materially open solution space, credible different directions, premature convergence, useful inversion/10x/alternate models, explicit deep brainstorm | Mechanical fixes, settled implementation, obvious maintenance, trivial refactor | Distinct candidate directions and evidence; the human owns product direction |
| design-stack | Meaningful visible UI, interaction, journey, responsive/state behavior, empty/loading/error/success states, accessibility, hierarchy, design-system alignment or frontend finish | No meaningful experience change | Experience decisions/prototype findings within settled product scope |
| Stacksmith | Real material choice of framework, DB, crawler, queue, hosting, agent SDK, vector DB, workflow engine, runtime, major dependency, build-versus-buy or infrastructure | Existing adequate stack, no choice open | Recommendation and trade-offs for TECH; no dependency installation merely to justify use |
| Jev Atlas | Potential bounded classification, ranking, recommendation, extraction, semantic QA/verification, fuzzy validation, scoring, moderation, triage, prioritization, matching, policy-like judgment or repeated LLM decisions | Deterministic change without semantic judgment | Applicability scan and evidence; may conclude NO HIGH-VALUE SEMANTIC-JUDGMENT OPPORTUNITY |

Atlas must compare applicable deterministic logic, ordinary LLM, retrieval, classical ML, human review, Jev and hybrid choices. Use micro-evaluation when needed. It discovers opportunities; it does not automatically choose Jev. Separate opportunity evaluation from stack/tool choice.

## Production-quality leaves

Load only a triggered leaf. The output is evidence or a constraint for truth/BUILD, not a new lifecycle.

| Risk/change | Addy leaf |
|---|---|
| Missing current framework pattern | source-driven-development |
| Consequential assumption needing adversarial challenge | doubt-driven-development |
| Durable quality bar absent or weakened | constraint-driven-development; detect and measure first, use real commands, keep enforced/measured/exception distinctions |
| Endpoint/module wire contract | api-and-interface-design |
| UI implementation constraints | frontend-ui-engineering |
| Browser-observed behavior | browser-testing-with-devtools, subject to real available browser tools |
| Auth, input, sensitive data, integrations, dependency threats | security-and-hardening, including its human Ask-first tier |
| Measured slowness / budget | performance-optimization |
| External consumers or production data migration | deprecation-and-migration |
| Pipeline/deployment automation | ci-cd-and-automation |
| Production signals and on-call needs | observability-and-instrumentation |
| Production rollout/rollback requirements | shipping-and-launch |
| Distinct review perspective | code-review-and-quality |

Preserve access to HumanLayer design-control-loop and build-iterated-agentic-loop for actual persistent control-loop work. Do not run them on every feature. Do not activate Addy's lifecycle commands or `using-agent-skills` as competing routers. PStack's future execution capabilities are not the implementation method for this pre-build skill.
